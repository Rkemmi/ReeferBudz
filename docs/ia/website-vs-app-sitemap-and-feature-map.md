# ReeferBudz Website vs App Sitemap and Feature Map

Status: Final
Date: August 7, 2026

## 1. Purpose

This document defines:

- the difference between the public website and the signed-in app
- which pages belong to each environment
- the purpose of each page or feature
- which features are public, member-only, shared, MVP, or later-phase
- how the product structure should remain clear as ReeferBudz expands

Its purpose is to prevent ReeferBudz from blurring the public brand site, the member platform, and future feature work into one unclear structure.

## 2. Core Structural Rule

ReeferBudz consists of two connected but distinct environments:

- the public website
- the signed-in member app

These environments must feel like parts of the same brand, but they must not be treated as the same product surface.

The public website exists to:
- explain
- introduce
- build recognition
- build confidence
- guide entry

The signed-in app exists to:
- onboard
- manage profiles and settings
- support discovery
- support member-only interaction
- handle member-only tools and controls

## 3. Public Website Definition

The public website is for people who have not yet entered the member experience, or who need public-facing information about the platform.

The public website must:

- explain what ReeferBudz is
- explain what ReeferBudz is not
- make the brand understandable quickly
- make privacy, safety, and community expectations visible
- provide legal and accessibility support
- guide adults toward the correct account-entry path

The public website must not try to function like the full member app.

## 4. Member App Definition

The member app is for authenticated users inside the member experience.

The member app must:

- support onboarding and member setup
- let members manage profile and settings information
- support privacy-conscious discovery
- provide member-facing safety and boundary tools
- support deeper social features only when the required safety structure exists

The member app must not feel like a generic dashboard or a detached utility product. It must remain clearly part of the ReeferBudz brand system.

## 8. Shared Structural Elements

These elements may appear across both the public site and the member app, but their purpose and behavior may differ by environment:

- brand identity
- primary navigation language
- footer logic where appropriate
- typography system
- color system
- privacy and safety cues
- legal links where needed

Shared elements must maintain continuity without causing confusion between public and member-only surfaces.

## 9. Public vs Member Boundary Rules

### Public Website Must Not Include

- member-only profile controls
- discovery tools
- private account settings
- member-only data
- features that imply full app functionality before account entry

### Member App Must Not Depend on Public-Site Explanation Alone

Once a member is inside the app, the member experience must be understandable on its own. Core member actions must not rely on public-site explanation to make sense.

### Boundary Rule

If a page’s main purpose is trust-building, explanation, public credibility, or account entry guidance, it belongs on the public website.

If a page’s main purpose is member action, member control, member visibility, or member-only interaction, it belongs in the app.

## 10. MVP Structure

### MVP Public Website

The MVP public website includes:

- homepage
- our story
- how it works
- safety
- contact
- community guidelines
- privacy
- terms
- accessibility
- sign-up or account-entry path

### MVP Member App

The MVP member app includes:

- sign-in entry
- sign-up entry
- onboarding
- member home
- profile
- settings
- discover Budz

### MVP Exclusions Unless Separately Approved

These should remain outside first-launch MVP unless deliberately pulled in later:

- messages
- matches
- search users
- live Budz
- recently live Budz
- events
- emergency contacts
- profile photo uploads
- broader direct-interaction or real-time community features

## 11. Structural Growth Rules

As ReeferBudz grows:

- new public pages must support clarity, trust, or conversion
- new member features must support community without weakening privacy or safety boundaries
- public and member surfaces must remain clearly separated in purpose
- no new feature should be added without a clear place in the product structure
- no feature should be added in a way that creates product-category confusion

## 12. Product Map Do's

ReeferBudz should:

- keep the website and app structurally distinct
- make page purpose explicit
- keep public pages trust-building and brand-facing
- keep app pages member-facing and task-oriented
- define later-phase features before building them
- use the sitemap to reduce confusion and product drift

## 13. Product Map Don'ts

ReeferBudz must not:

- blur public pages with member-only tools
- put high-risk or high-sensitivity features into MVP by accident
- treat every idea as a launch feature
- let later-phase features distort the first stable product structure
- create duplicate page purposes across website and app
- build features with no clear product home

## 14. Short Structural Statement

ReeferBudz uses a two-part product structure: a public website for brand, trust, and entry, and a member app for onboarding, profiles, settings, discovery, and future community features added in a controlled order.
